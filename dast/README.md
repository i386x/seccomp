# Dynamic Application Security Testing with RapiDAST

To run RapiDAST on Trustify (TPA v2) you need to first setup infrastructure
with the Trustify services up and running. To make this task as easy as
possible this repository comes with the `run.sh` helper script.

## Running All Analysis Tasks at Once

To run all analysis tasks, run

```sh
$ ./run.sh all
```

This will

1. create `.workspace` workspace directory in the same directory as `run.sh` is
1. clone [RapiDAST](https://github.com/RedHatProductSecurity/rapidast)
   repository into it
1. create a Python virtual environment and install RapiDAST runtime
   dependencies inside it
1. spawn the container with Trustify service
   * this may also build the custom container image with `trustd`
   * environment variables that can be used to customize this step:
     * `TRUSTIFICATION_REGISTRY` - the container registry with Trustify images
       (default: `ghcr.io/trustification`)
     * `TRUSTD_IMAGE` - the name of the Trustify image (default: `trustd`)
     * `TRUSTD_VERSION` - the tag/version of the Trustify image (default:
       `latest`)
     * `TRUSTD_VERSION_DAST` - the tag/version used to tag the customized
       `TRUSTD_IMAGE` (default: `dast`)
1. run RapiDAST on exposed APIs of the Trustify service
1. stop the container

Then you can run

```sh
$ ./run.sh serve
```

and access the reports from your browser via localhost: http://0.0.0.0:8765/
In case the default HTTP port 8765 is taken you can pass your own chosen port
number to the `serve` command:

```sh
$ ./run.sh serve 8484
```

## Running Analysis Tasks Step-by-Step

The `run.sh` script has also commands to gain more control over the whole
analysis process. This become useful mostly during debugging.

### Initializing or Updating Your Work Space

Run `./run.sh init` and you will get:

* `./.workspace` under the same directory where the `run.sh` is present
* cloned [RapiDAST](https://github.com/RedHatProductSecurity/rapidast)
  repository inside `./.workspace/rapidast`
* created Python virtual environment at `./.workspace/.venv` with all RapiDAST
  runtime dependencies preinstalled

To update the RapiDAST repository, just run `./run.sh update`. This will also
initialize your work space (`./.workspace`) if you have no one yet.

### Building a Container Image Providing the Trustify Service

**Prerequisites:** initialized work space.

You can (re)build the customized Trustify container image by running

```sh
$ ./run.sh build
```

This creates a customized container image, if it does not exist yet, which is
necessary to run `trustd` in PM mode (that is in a mode where no additional
infrastructure is needed) inside a container. To rebuild the existing one, pass
`-f` or `--force` flag to the command. This will also stop and remove all
containers that use the image.

Environment variables `TRUSTIFICATION_REGISTRY`, `TRUSTD_IMAGE`, and
`TRUSTD_VERSION` specify the `trustd` base image. The output image will be
named the same as `${TRUSTD_IMAGE}` and it will be tagged with
`${TRUSTD_VERSION_DAST}`.

### Spawning the Container Providing the Trustify Service

**Prerequisites:** initialized work space.

To spawn the container with the Trustify service, run

```sh
$ ./run.sh cstart
```

This will also build the image if it does not exist. As before,
`TRUSTIFICATION_REGISTRY`, `TRUSTD_IMAGE`, `TRUSTD_VERSION`, and
`TRUSTD_VERSION_DAST` specify the base and the output image during the build
phase. The name of the spawned container will be
`${TRUSTD_IMAGE}_${TRUSTD_VERSION_DAST}`.

### Listing All Spawned Containers and Services

**Prerequisites:** initialized work space.

To get the list of all spawned containers and services together with their
status, run

```sh
$ ./run.sh clist
```

The `clist` command accepts the same options as `podman ps` command.

### Seeing the Logs of the Spawned Container

**Prerequisites:** initialized work space.

To see the logs of the spawned container, run

```sh
$ ./run.sh clogs
```

The `clogs` command accepts the same options as `podman logs` command.

### Running RapiDAST on the Particular API

**Prerequisites:** initialized work space, necessary containers and services up
and running.

To run RapiDAST on the particular API, run

```sh
$ ./run.sh dast API
```

where `API` is one of:
* `trustify` (runs RapiDAST on Trustify API)

After the command finished successfully, you can see the analysis reports in
your browser by running `./run.sh serve` and visiting http://0.0.0.0:8765/ as
mentioned earlier.

### Seeing the Reports Generated by RapiDAST

**Prerequisites:** initialized work space, successfully finished RapiDAST
analysis.

To see the reports generated by RapiDAST in your browser, run

```sh
$ ./run.sh serve
```

and go to http://0.0.0.0:8765/ (you can change the port if it is taken by
passing its number to the `serve` command, e.g. `./run.sh serve 8484`).

### Stopping the Spawned Container

**Prerequisites:** initialized work space.

To stop the spawned container, run

```sh
$ ./run.sh cstop
```

### Cleaning Up

**Prerequisites:** initialized work space (only if running without `-a` or
`--all`).

To remove all reports generated by RapiDAST and other intermediate products,
run

```sh
$ ./run.sh clean
```

By adding `-a` or `--all` flag, the entire work space directory will be
removed, together with built images and containers specified by `TRUSTD_IMAGE`,
`TRUSTD_VERSION`, and `TRUSTD_VERSION_DAST` environment variables.
